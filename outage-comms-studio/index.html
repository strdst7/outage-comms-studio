Built for the person who has to press “send” during an outage

When the network goes down, the technical timeline is full of jargon, guesses and half-confirmed causes. Customers hear something different on every channel, support gets flooded, and well-meant ETAs become broken promises. This tool turns one checked set of facts into every channel message — consistently.

Who it's for

Outage comms lead / duty manager in network ops who owns customer updates under time pressure.

Problem it solves

Inconsistent, jargon-heavy updates across SMS, app, status page and support — with invented ETAs and hidden uncertainty.

Outcome you get

A ready-to-send update pack: checked facts, 7 channel-ready messages, pre-send checklist and exportable log.

How it works

Four steps. No account, no upload — everything stays in your browser.

  1. Set the incident — area, services, next update time, tone.
  2. Build the timeline — log what happened and how sure you are.
  3. Check the facts — jargon, risky promises and unknowns flagged automatically.
  4. Send with confidence — copy each channel message, tick the checklist, export the pack.

          How to use this in a real incident (and what it won't do)

          1

          Start from facts, not drafts

          Fill in only what the network team has confirmed. If the cause is unknown, leave it blank — messages will honestly say “still investigating” instead of inventing a story.

          2

          Never promise a fix time

          Give a next update time instead. The tool flags ETA promises (“fixed by 2pm”, “within 3 hours”) and rewrites them as update commitments.

          3

          One pack, every channel

          Copy SMS, push, status page, social, email, support script and IVR from the same checked facts. Export the pack for the incident record.

          Data & safety — read this
          • Fictional by default: the sample scenario is synthetic. No real customer data, network telemetry or provider branding is used.
          • Uncertainty is labelled: “Likely” and “Unknown” items are worded as such in every message. User reports are never presented as verified coverage data.
          • Your data stays here: everything is stored only in your browser (localStorage). Nothing is uploaded. Clear it anytime with “Clear all”.
          • Human approval required: the checklist and duty-manager sign-off are part of the workflow — the tool never auto-sends anything.
